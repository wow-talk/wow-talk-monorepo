# 02. next/font와 metadata (2026-05-20)

> Next.js의 `next/font/google`로 폰트 3종(serif/sans/mono)을 self-host하고, layout의 `metadata` export로 SEO/탭 타이틀을 설정. DESIGN.md의 비공개 폰트(Copernicus/StyreneB)는 Google Fonts 대체로 매핑.

## 어디서 (Where)

- `src/app/layout.tsx` — 폰트 3종 로드 + html className에 변수 주입 + metadata export
- `src/styles/tokens.ts` — font family 토큰이 `var(--font-serif/sans/mono)` chain으로 layout의 변수와 연결됨

## 무엇을 (What)

### 폰트 로드 3종

```ts
import { Cormorant_Garamond, Inter, JetBrains_Mono } from "next/font/google";

const serif = Cormorant_Garamond({
  subsets: ["latin"],
  weight: ["400", "500"],
  variable: "--font-serif",
  display: "swap",
});
const sans = Inter({ subsets: ["latin"], variable: "--font-sans", display: "swap" });
const mono = JetBrains_Mono({ subsets: ["latin"], variable: "--font-mono", display: "swap" });
```

`<html>`에 세 변수 적용:

```tsx
<html lang="ko" className={`${serif.variable} ${sans.variable} ${mono.variable}`}>
```

이로써 CSS에서 `var(--font-serif)`, `var(--font-sans)`, `var(--font-mono)`로 접근 가능.

### tokens.ts에서 활용

```ts
font: {
  serif: 'var(--font-serif), "Cormorant Garamond", Garamond, "Times New Roman", serif',
  sans: 'var(--font-sans), Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif',
  mono: 'var(--font-mono), "JetBrains Mono", "Courier New", monospace',
}
```

`vars.font.serif`를 컴포넌트 CSS에서 쓰면 next/font의 자체 호스팅 파일이 1순위로 적용되고, 다운로드 전에는 fallback chain으로 자연스럽게 표시.

### metadata export

```ts
export const metadata: Metadata = {
  title: "wow-talk",
  description: "WebSocket inspector chat demo",
};
```

App Router는 layout/page의 `metadata` named export를 자동으로 인식해 `<head>`에 주입. 컴포넌트 named export와는 다른 룰이라 layout.tsx에 같이 두어도 OK(헌법 6번 조항 보강 참고).

## 왜 (Why)

### 1) Copernicus/StyreneB는 비공개라 대체 결정

DESIGN.md는 Anthropic 자사 폰트인 Copernicus(serif), StyreneB(sans)를 디스플레이/본문에 지정. 둘 다 라이선스 보호로 공개 CDN 없음. DESIGN.md 자체가 대체안(Cormorant Garamond / EB Garamond / Tiempos Headline for serif, Inter / Söhne for sans)을 명시.

선택:

| 의도 | 채택 | 근거 |
|---|---|---|
| serif (Copernicus) | Cormorant Garamond | DESIGN.md "닫힌 환경에서 가장 가까운 오픈소스 근사" 명시. Google Fonts 무료. |
| sans (StyreneB) | Inter | DESIGN.md "humanist 비례가 가장 비슷한 매칭" 명시. 가장 많이 쓰임. |
| mono | JetBrains Mono | DESIGN.md 원본 자체가 JetBrains Mono. 변경 불필요. |

### 2) next/font가 self-host하는 이유

전통적으로 Google Fonts는 `<link>`로 외부 CDN 호출 → 첫 페인트 지연 + 외부 의존. `next/font/google`은 **빌드 타임에 폰트 파일을 다운로드해서 프로젝트 정적 자산에 포함**시킴. 결과:

- 첫 페인트 시 외부 네트워크 없음 → FCP/LCP 개선
- CDN 장애에 무관
- 자동 `font-display: swap` 적용으로 폰트 다운로드 동안 fallback 표시(텍스트 안 보이는 시간 0)
- 자동 preconnect, prefetch 헤더 관리

### 3) variable로 CSS 변수 노출

`variable: "--font-serif"`를 주면 next/font가 그 클래스가 적용된 element 하위에서 `--font-serif: "Cormorant_Garamond_xxx", fallback...` 형태로 CSS 변수를 세팅. 이를 `tokens.ts`의 fallback chain 맨 앞에 두면 vanilla-extract `vars.font.serif`가 자연스럽게 next/font 결과를 1순위로 사용.

### 4) `display: swap`

폰트 다운로드 중에는 fallback(예: Garamond) 표시 → 다운로드 완료 시 교체. 텍스트가 안 보이는 시간(FOIT) 회피. 살짝 어색한 폰트 점프(FOUT)는 트레이드오프지만 UX 상 FOIT보다 나음.

## Before / After

### Before — `layout.tsx` (보일러플레이트)

```tsx
import { Geist, Geist_Mono } from "next/font/google";

const geistSans = Geist({ variable: "--font-geist-sans", subsets: ["latin"] });
const geistMono = Geist_Mono({ variable: "--font-geist-mono", subsets: ["latin"] });

export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};

<html lang="en" className={`${geistSans.variable} ${geistMono.variable}`}>
```

- 디자인 시스템 무관한 Geist 폰트.
- 한국어 페이지인데 `lang="en"`.
- 빈 description.

### After — `layout.tsx`

```tsx
import { Cormorant_Garamond, Inter, JetBrains_Mono } from "next/font/google";
import "@/styles/globals.css";

const serif = Cormorant_Garamond({ subsets: ["latin"], weight: ["400","500"], variable: "--font-serif", display: "swap" });
const sans  = Inter({ subsets: ["latin"], variable: "--font-sans", display: "swap" });
const mono  = JetBrains_Mono({ subsets: ["latin"], variable: "--font-mono", display: "swap" });

export const metadata: Metadata = {
  title: "wow-talk",
  description: "WebSocket inspector chat demo",
};

<html lang="ko" className={`${serif.variable} ${sans.variable} ${mono.variable}`}>
```

- 디자인 시스템에 맞는 3종 패밀리.
- `lang="ko"`로 한국어 페이지 명시.
- 의미 있는 metadata.

## 장단점 (Trade-offs)

- **채택안: next/font/google + variable**
  - 장점: self-host로 성능 좋음, CSS 변수로 vanilla-extract와 깔끔 연동, 라이선스 안전.
  - 단점: 빌드 타임 다운로드라 첫 빌드 살짝 길어짐, Google Fonts 의존(인터넷 필요).
- **미채택안: 로컬 .woff2 파일 직접 호스팅 (`next/font/local`)**
  - 장점: 인터넷 무관, 폰트 파일 버전 고정.
  - 단점: 파일을 직접 받아 repo에 커밋(라이선스 확인 필요), variants 관리 번거로움.
- **미채택안: CDN `<link>`**
  - 장점: 셋업 0.
  - 단점: 외부 의존, 자동 swap/preconnect 없음, 첫 페인트 지연.

## 영향 (Impact)

- **성능**: 첫 페인트 외부 네트워크 0회. font-display: swap으로 FOIT 회피.
- **번들/정적 자산**: Cormorant + Inter + JetBrains 3종 woff2가 정적 자산에 포함. 가벼운 편(latin subset만 받으면 가족당 50KB 이하).
- **타이포 일관성**: vanilla-extract `vars.font.*`만 참조하면 됨. 컴포넌트가 폰트 패밀리를 임의로 적지 않음.
- **국제화**: `lang="ko"` 명시로 스크린리더 + 검색엔진 한국어 페이지 인식.
